# ADR-0001 在充电量真源：以脉冲流水重放为准

状态：已选定（全局唯一口径，不得与「累计列为准」混用）
日期：2026-11-24
范围：仅覆盖**电量真源**。计价档、关账争用另立需求，不在本 ADR 内。

## 决策

`pulses`（脉冲流水）是会话电量的**唯一真源（source of truth）**。
`sessions.kwh`（会话累计电量列）只是**加速缓存**，本身不具有权威性。

任何展示口径（总览在充电量、会话详情、会话册列、记脉冲页、对齐诊断条）与关账前的电量，
都必须能由流水重放得到：

```
replay_kwh(session) = SELECT COALESCE(SUM(delta_kwh),0) FROM pulses WHERE session_id=?
```

## 备选与取舍

- 方案 A「以会话累计电量列为准」：实现简单，但天然允许旁路只改累计列，
  无法满足「禁止只改累计数字」「旁路改数不得伪装成脉冲成功」，否决。
- 方案 B「以脉冲流水重放为准」（**选定**）：累计列可随时由流水重建，
  旁路改累计列在库层即被拒绝或整笔回滚，半截脉冲只会让缓存标陈旧、可被自愈，不会长期分叉。

## 必须成立的不变量

1. **可重放**：每个对外电量数字都能追溯到一组脉冲流水；关账前必须重放一次。
2. **同刷（单事务）**：脉冲写口在同一事务内写 `pulses` 流水、校准 `sessions.kwh` 缓存、
   写脉冲回执、写事件；要么全成要么全滚，不存在「列已加流水缺行 / 流水齐全列未动」的提交态。
3. **旁路不伪装**：直接 `UPDATE sessions SET kwh` 的旁路在库层被触发器拒绝（整笔回滚），
   并记 `bypass_audit`；旁路绝不产生脉冲回执，绝不盖过重放结果。
   夹具放行的旁路仅用于复现故障，放行通道与脉冲写口物理隔离。
4. **流水只追加**：`pulses` 禁 UPDATE/DELETE，保证重放结果不可被悄悄改写。
5. **陈旧显式标注**：缓存列与重放不一致时，对齐诊断条与各页面标 `陈旧`，禁止亮「已对齐」；
   读侧可自愈（以重放结果校准缓存并留旁路审计痕迹），但展示始终先给重放值。
6. **并发不漂格**：脉冲写口用 `BEGIN IMMEDIATE` 串行化，双脉冲并发各拿各的写锁，
   两笔都完整落库，重放合计 = 两笔增量之和。
7. **半截脉冲不分叉**：只落一侧（只有流水或只有列改动）的事务无法提交；
   若经夹具注入半截状态，诊断条立即标陈旧并可自愈，不会长期分叉。

## 臂内自洽约定（实现自由度内的具体选择）

- 何时校准累计列：每次脉冲写口事务内校准；读侧重放发现漂移时自愈校准；关账前再校准一次。
- 陈旧如何标：`alignment` 字段取 `已对齐` / `陈旧`，诊断条以会话为粒度给出重放值、缓存值、差值与原因。
- 拒因：旁路写库由 SQLite 触发器 RAISE(ABORT)，服务层翻译为 `BypassRejected`，
  并在 `bypass_audit` 留痕（放行夹具的注入同样留痕，类别为夹具注入）。
